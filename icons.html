Why icons get their own spec

Hero/cover imagery is expressive and can tolerate some looseness — it's decoration. Icons are functional: read at 24–48px, sitting next to body copy, needing to stay perfectly consistent stroke-to-stroke across 30–50+ symbols. That's a vector-precision problem, not a generative one — AI image generation would hit the same control issues seen on early hero-image tests, at a scale where it's far more visible.

Design rules

Grid24×24px artboard, 2px padding on all sides — matches Lucide, Radix Icons, Feather
Stroke1.5–2px, consistent across the entire set — pick one weight and never mix
Caps / joinsRounded, to match the softness of the hero imagery's linework
StyleOutline/line-art only — no filled icons, no duotone, no mixed fill+stroke
ColorSingle color per icon. FusionX Lime for primary/active, Secondary Text token for neutral/inactive. Status tokens only on status-specific icons — never blend into a feature icon
EffectsNo gradients, no shadows, no glow

Production method

Sourced from Lucide (ISC license — free for commercial use, no attribution required, ~1,700 icons, a maintained fork of Feather Icons) rather than hand-drawn or AI-generated. Each matched icon was pulled from the lucide-static package, stripped of its default class/license comment, and had its stroke weight standardized from Lucide's default 2px down to 1.5px to match the FusionX spec — one consistent weight across the set, per the design rules above.

Icons render inline via currentColor, so the same file can show as Lime, Secondary Text, or a Status color just by the CSS class wrapping it — no separate colored copies needed for web/HTML collateral. This does not work in InDesign — currentColor is a browser/CSS concept with no equivalent there, so InDesign resolves it to a static black with no live link back to a swatch, and you can't recolor it through the Swatches panel like a native shape. For InDesign (or any placement outside a browser), use the pre-baked color variant folders instead: assets/icons/on-dark/ (#F7F7F7, for dark or accent backgrounds), assets/icons/on-light/ (#4D4D4D, for light backgrounds), and assets/icons/accent-green/ (#6EE600, for brand-accent emphasis) — same filenames as the base set, color already fixed in the file, so InDesign just reads it correctly on place.

Each of those three color variant folders also has a png/ subfolder with rasterized copies at 24px, 128px, and 512px, transparent background — for anywhere a vector file isn't accepted (Slack, docs, slides, PowerPoint). See LICENSE-ICONS.md for the exact paths.

One concept — Hybrid / Multi-cloud — has no direct Lucide equivalent and still needs hand-drawing on the same grid/stroke spec, along with a literal Kubernetes mark if brand-accurate K8s iconography is ever required (the current "Kubernetes / Container" entry uses a generic container glyph as a placeholder, not the K8s logo).
