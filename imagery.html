Imagery System

Abstract by default. Real where it needs to be trusted.

One direction — the hero/cover treatment — is tested and confirmed. Section dividers and data-viz backgrounds follow the same construction logic but aren't yet generated as a full set.

Core rule

Split imagery into two categories and never blend them:

  • Decoration (covers, dividers, backgrounds) — abstract, geometric, data-derived. Never stock photography, never literal hardware rendered as art, never gradients or glow/bloom.
  • Credibility (data centers, control rooms, engineers at work) — documentary photography of actual environments. Never staged, never stock/lifestyle.

This split holds across every collateral type — what changes is how much of each you use, and how bold or restrained.

Generative prompt scaffold

Every prompt is built from the same six slots, in order — consistency comes from the scaffold, not the wording.

[SUBJECT/FORM]      mesh, wireframe lattice, node network, layered plane
[CONSTRUCTION]      isometric / flat 2D / thin-line wireframe / faceted low-poly
[PALETTE]           exact hex values, max 2-3 colors + dark background
[LINE TREATMENT]    stroke weight, opacity, glow behavior
[COMPOSITION]       placement, density, negative space
[NEGATIVE CONSTRAINTS] explicit exclusions

Standing negative constraints, every prompt:

no gradients, no glassmorphism, no drop shadows, no literal hardware
(no servers, racks, chips, cables, gears), no photorealistic rendering,
no people, no stock-photo aesthetic, no glossy/plastic surfaces

Confirmed direction — hero / cover

Layered wireframe terrain ridges, tonal gradation from white/pale neutral at the far ridges into FusionX Lime (#6EE600) at the nearest ridge. Tonal gradation — not flat color — is what reads as premium and restrained; a single fully-saturated green mesh reads generic (confirmed anti-pattern from an earlier test). Terrain occupies the bottom 35–40% of frame with generous negative space above for logo/headline.

Section dividers and data-viz backgrounds follow the same negative-constraint logic at lower visual weight — dividers use a single simplified fragment, data-viz backgrounds sit at 10–15% opacity so they recede behind charts instead of competing.

Once generation scales up, saved assets live in /assets/images/ following this structure — folders are already scaffolded in this repo:

  /dataviz-background/  fusionx-[brief-name]-dataviz-bg-v[n]
  /rejected/             off-brand generations kept as reference

Keep a running log of which exact prompt produced which kept asset — that's what makes this reusable across briefs instead of starting from zero each time.

Diagrams & data visualization

Distinct from the generative imagery above — diagrams, charts, tables, and infographics carry structured information, not decoration or credibility photography. They follow their own rule: single-accent tonal system, not multi-hue category coding. FusionX has one dedicated accent (Lime) and no dedicated secondary hue of its own — a second color is only ever borrowed from Corporate Blue, and only when a genuinely distinct data series or link requires it. Status colors are reserved for status and must never be repurposed as decorative category coding on a diagram.

DoDon't
One accent (Lime) carrying emphasis, everything else in the neutral rampA different saturated hue per layer/category "for legibility"
A second hue only for a genuinely distinct data series or link (Corporate Blue)Borrowing Warning/Success/Error hues for decorative coding
Opacity/lightness steps of one hue for sequential or ranked dataInventing new hues (gold, teal, etc.) that aren't in the token library
